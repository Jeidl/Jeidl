# 拉片方法：如何拆解一支预告并补充本知识库

> Summary: 用逐帧拆解把"感觉"变成数据，再把数据写回知识库。

## Context
本知识库的时长数字多为经验法则。拉片得到的实测数据可以校准它们。

## 步骤
1. 找官方高清版本，确认帧率（24 / 25 / 30）。
2. 在剪辑软件里逐镜打点（场景检测可以辅助，但要人工复核）。
3. 每一镜填写记录表（与分镜表字段一致，便于对比）。
4. 标出结构点：冷开场结束、转折①、呼吸点、第三幕开始、最大一击、片名、按钮。
5. 只听音频再过一遍：标 hit、静默、音乐段落和 BPM。
6. 计算指标，写结论。

## 记录表
| 镜号 | 入点 | 出点 | 帧数 | 段落 | 景别 | 画面 | 停/爆 | 速度 | 音乐段 | 音效 / hit | 台词 | 字幕卡 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|

## 指标
| 指标 | 计算 |
|---|---|
| 各幕平均镜长（ASL） | 该幕时长 ÷ 镜头数 |
| 每分钟剪辑数 | 镜头数 ÷ 分钟 |
| 镜长分布 | 最短、最长、中位数（Cinemetrics 的做法是记录每一镜的时长，而不只是平均值【S14】） |
| hit 数 | 小 / 中 / 大三级分别统计 |
| 真空点 | 次数与时长 |
| 慢镜 | 次数与总时长 |
| 字幕卡 | 张数、平均停留时间 |
| 台词 | 句数、总时长 |
| BPM | 各段速度 |

## 写回知识库
- 新建 `topics/case-studies/case-<片名拼音或英文>.md`，id 为 `YYYYMMDD-case-<slug>`。
- 写清"事实（带来源或注明'本人拉片'）"和"对预告的启示"。
- 如果实测数据与某条经验法则明显不符，更新那条笔记并更新 `updated` 日期。
- 在 INDEX.md 注册表和 case-studies/_topic.md 中登记。
